# Инструкция: RAG без локальной LLM (облегчённая версия)

> **Этот вариант** использует Ollama **только для эмбеддингов** (274 MB вместо 2.7 GB).
> Ответы генерирует Claude — он гораздо умнее локальной 3B модели.
> Если вам нужен полностью автономный RAG-пайплайн — смотрите [README_FULL.md](README_FULL.md).

Пошаговая инструкция «для чайников». Цель — установить систему на чистый Windows-компьютер,
проиндексировать рабочий проект и вики, и задавать вопросы через Claude в VS Code.

**Сценарий из этой инструкции:**

```
C:\git\MyProject\   — моно-репозиторий с большим проектом (.cs, .py, .md, .json, ...)
C:\git\wiki\        — репозиторий с вики-документацией (.md файлы)
```

### Чем отличается от полной версии?

| | Полная (FULL) | Облегчённая (LITE) |
|---|---|---|
| Ollama модели | nomic-embed-text (274 MB) + qwen2.5:3b (2 GB) | **только** nomic-embed-text (274 MB) |
| Кто генерирует ответы | Локальная LLM (qwen2.5:3b) | **Claude** (через VS Code) |
| Качество ответов | Среднее (3B модель галлюцинирует) | **Высокое** (Claude гораздо мощнее) |
| Доступные инструменты | Все 5 | 3 из 5 (`index_folder`, `find_relevant_docs`, `index_status`) |
| Работает без интернета | Да (полностью локально) | Нет (нужен Claude API) |
| Скачивать | ~2.7 GB | ~274 MB |

## Шаг 1. Установка Python 3.12

> ChromaDB не работает с Python 3.14. Нужна версия 3.11 или 3.12.

1. Скачайте Python 3.12 с https://www.python.org/downloads/release/python-3128/
2. При установке **обязательно** поставьте галочку **"Add Python to PATH"**
3. Проверьте:

```cmd
python --version
```

Ожидаемый вывод: `Python 3.12.x`

> Если у вас несколько версий Python, используйте `py -3.12` вместо `python` во всех командах ниже.

---

## Шаг 2. Установка Ollama (только для эмбеддингов)

Ollama нужна для одной вещи — превращать текст в вектора (эмбеддинги), чтобы ChromaDB мог искать по смыслу.

1. Скачайте с https://ollama.com/download (Windows)
2. Установите и запустите
3. Откройте **новый** терминал и скачайте **только модель эмбеддингов**:

```cmd
ollama pull nomic-embed-text
```

Это скачает **274 MB** (не 2.7 GB как в полной версии).

4. Проверьте:

```cmd
ollama list
```

Ожидаемый вывод:

```
NAME                 ID           SIZE     MODIFIED
nomic-embed-text     ...          274 MB   ...
```

> LLM-модель (`qwen2.5:3b`) **не нужна** — ответы будет генерировать Claude.

## Шаг 3. Клонирование и установка RAG

```cmd
cd C:\git
git clone https://github.com/TheJubadze/OtusAiForDevs.git
cd OtusAiForDevs\RAG
```

Создайте виртуальное окружение и установите зависимости:

```cmd
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

> Если `python -m venv` не работает — попробуйте `py -3.12 -m venv venv`

## Шаг 4. Индексация проекта и вики

### 4.1. Настройте пути

Скопируйте файл настроек и отредактируйте его:

```cmd
copy .env.example .env
notepad .env
```

Укажите свои папки (через `;`):

```ini
INDEX_FOLDERS=C:\git\MyProject;C:\git\wiki
CHROMA_PATH=C:\git\rag_index
COLLECTION_NAME=my_project
```

### 4.2. Запустите индексацию

```cmd
python index_my_project.py
```

Пример вывода:

```
Создаю VectorStore...

Индексирую: C:\git\MyProject (с нуля)
  Загружено файлов: 347
  Создано чанков:   1420
  Всего в индексе:  1420

Индексирую: C:\git\wiki (добавляю)
  Загружено файлов: 89
  Создано чанков:   310
  Всего в индексе:  1730

Готово! Индекс сохранён в: C:\git\rag_index
```

> **Время индексации** зависит от объёма файлов. 500 файлов ~ 2-5 минут.
> **Переиндексация:** запустите скрипт заново — индекс пересоздастся с нуля.

## Шаг 5. Подключение к Claude Code (VS Code)

### 5.1. Установите Claude Code

Если ещё не установлен:

```cmd
npm install -g @anthropic-ai/claude-code
```

> Нужен Node.js. Скачать: https://nodejs.org/

### 5.2. Добавьте MCP-сервер

Откройте терминал и выполните:

```cmd
claude mcp add rag-knowledge-base ^
  -e CHROMA_PATH=C:\git\rag_index ^
  -e COLLECTION_NAME=my_project ^
  -- python C:\git\OtusAiForDevs\RAG\server.py
```

> Обратите внимание: мы **не передаём** `LLM_MODEL` — он не нужен для поиска документов.

### 5.3. Проверьте подключение

Откройте VS Code, запустите Claude Code и напишите:

```
Покажи статус индекса
```

Ожидаемый ответ:

```
Статус индекса:
- Коллекция: my_project
- Чанков в индексе: 1730
- Путь к базе: C:\git\rag_index
```

## Шаг 6. Использование

### Как задавать вопросы

Пишите Claude запросы вида:

```
Найди в нашей документации информацию про авторизацию и расскажи, как она работает
```

Claude вызовет `find_relevant_docs`, получит найденные фрагменты из вашего проекта и вики,
и **сам** сгенерирует ответ на основе этих фрагментов. Claude гораздо умнее локальной 3B модели,
поэтому ответы будут качественнее.

### Примеры запросов

**Поиск по документации:**
```
Найди документы про деплой и расскажи процесс развёртывания
```

**Поиск по коду:**
```
Найди в проекте код, связанный с обработкой ошибок, и объясни паттерн
```

**Ревью архитектуры:**
```
Найди документацию про архитектуру проекта и предложи улучшения
```

**Онбординг нового разработчика:**
```
Найди в вики всё, что нужно знать новому разработчику для старта
```

### Какие инструменты доступны

| Инструмент | Что делает | Нужна LLM? |
|---|---|---|
| `find_relevant_docs` | Поиск документов по смыслу | Нет |
| `index_folder` | Индексация новой папки | Нет |
| `index_status` | Статус индекса | Нет |
| `ask_question` | Полный RAG-пайплайн (Corrective RAG) | **Да** (не будет работать) |
| `summarize_document` | Суммаризация файла | **Да** (не будет работать) |

> `ask_question` и `summarize_document` требуют локальную LLM.
> Но вам они не нужны — Claude делает то же самое, только лучше.

### Как это работает

```
Ваш вопрос
    │
    ▼
Claude (мощная модель)
    │
    ├─ вызывает find_relevant_docs
    │       │
    │       ▼
    │  ChromaDB ищет похожие фрагменты
    │  (используя эмбеддинги от nomic-embed-text)
    │       │
    │       ▼
    │  Возвращает 5 самых релевантных фрагментов
    │
    ▼
Claude читает найденные фрагменты
и генерирует качественный ответ
    │
    ▼
Ответ вам
```

## Советы

### Большой репозиторий — что индексировать?

Если в моно-репозитории 10 000+ файлов, лучше индексировать только нужные папки.
Укажите их в `.env`:

```ini
INDEX_FOLDERS=C:\git\MyProject\docs;C:\git\MyProject\src\backend;C:\git\wiki
```

### Как обновить индекс после `git pull`?

Запустите `python index_my_project.py` заново.

### Переиндексация через Claude

Можно прямо из чата:

```
Проиндексируй папку C:\git\wiki с нуля
```

### Какие файлы индексируются?

Все текстовые: `.md`, `.txt`, `.py`, `.cs`, `.js`, `.ts`, `.java`, `.go`, `.yaml`, `.json`, `.xml`, `.html`, `.css`, и т.д.

Бинарные файлы (картинки, .dll, .exe) пропускаются автоматически.

## Устранение проблем

### `ModuleNotFoundError: No module named 'chromadb'`

Вы не в виртуальном окружении:

```cmd
cd C:\git\OtusAiForDevs\RAG
venv\Scripts\activate
```

### `ConnectionError: ... localhost:11434`

Ollama не запущена. Запустите приложение Ollama (иконка в трее).

### `Python 3.14 ... ConfigError`

Установите Python 3.12 и пересоздайте venv:

```cmd
py -3.12 -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### Claude Code не видит MCP-сервер

```cmd
claude mcp list
```

Если `rag-knowledge-base` нет в списке — добавьте заново (Шаг 5.2).
