# RAG Knowledge Base — MCP-сервер с локальной LLM

MCP-сервер, который превращает локальную папку с документами в интерактивную базу знаний. Claude подключается к нему и может искать информацию, задавать вопросы и получать ответы — полностью локально, без внешних API.

**Стек:** Python 3.12 · LangGraph · LangChain · ChromaDB · Ollama · FastMCP · pytest · Docker

---

## Что построено

### Corrective RAG граф (LangGraph)

Запрос проходит через цепочку узлов с автоматическими повторными попытками:

```
rewrite_query → retrieve → grade_chunks → generate → hallucination_check
                               ↑                              |
                               └──── prepare_retry ←──────────┘
                                     (до 2 попыток)
```

| Узел | Что делает |
|------|------------|
| `rewrite_query` | Переформулирует запрос для лучшего поиска |
| `retrieve` | Гибридный поиск: векторный + BM25 |
| `grade_chunks` | LLM отфильтровывает нерелевантные чанки |
| `generate` | Генерирует ответ строго по контексту |
| `hallucination_check` | Проверяет, что ответ основан на документах, а не выдуман |
| `prepare_retry` | При неудаче — переформулирует запрос и повторяет |

### MCP-сервер (FastMCP) — 5 инструментов

| Инструмент | Описание |
|------------|----------|
| `index_folder` | Индексация папки с документами в ChromaDB |
| `ask_question` | Полный RAG-пайплайн с Corrective RAG |
| `find_relevant_docs` | Поиск чанков без генерации ответа |
| `summarize_document` | Краткое содержание конкретного файла |
| `index_status` | Статистика индекса |

### Тестовая база знаний — Правила движения единорогов

Для демонстрации индексировались **Правила движения единорогов по Тилимилитрямдии (ПДЕ-Т)** — документ с уникальной терминологией (рогосигнал, радуготропа, лунный светофор), которой нет ни в каком обучающем корпусе моделей. Это хороший стресс-тест для RAG.

## Как шла разработка

Проект строился итерационно: каждая версия работала, но имела конкретный изъян, который устранялся на следующем шаге.

**v1 — базовый поиск:** `DirectoryLoader` → чанки по 500 символов → ChromaDB с дефолтными эмбеддингами → вопрос к LLM. Работает, но на вопрос «Как работает авторизация?» находит `sprint_workflow.md` вместо `auth_flow.md`.

**v2 — лучшие эмбеддинги:** Заменили `all-MiniLM-L6-v2` на `nomic-embed-text` через Ollama. Поиск по русскому тексту сразу стал точнее. Но LLM (3B параметров) начала галлюцинировать — выдумывала «исторического инженера» и несуществующие команды.

**v3 — строгий промпт + крупные чанки:** Добавили запрет на выдумки в системный промпт, увеличили чанки с 500 до 1000 символов. Галлюцинации уменьшились, но не исчезли — нужна архитектурная защита.

**v4 — Corrective RAG:** Переписали на LangGraph с грейдингом чанков и проверкой галлюцинаций. При неудаче — переформулировка запроса и повторный поиск. Плюс гибридный поиск BM25 + вектор.

**Финал:** MCP-сервер на FastMCP, Docker Compose (GPU и CPU версии), 42 теста.

## Интересные проблемы

### Python 3.14 не совместим с ChromaDB

Установлен preview Python 3.14 — ChromaDB падает с `ConfigError` в Pydantic v1. Решение простое: откатиться на Python 3.12 и пересоздать venv. Но неочевидно, что именно версия Python — причина, а не версия библиотеки.

### Дефолтные эмбеддинги плохо работают с русским текстом

`all-MiniLM-L6-v2` (дефолт ChromaDB) обучена преимущественно на английском. Запрос «авторизация» не находил файл `auth_flow.md`. Переход на `nomic-embed-text` через Ollama — и поиск сразу заработал правильно.

### Маленькие чанки разрезают контекст

Чанки по 500 символов разрезали разделы документов посередине. Раздел про JWT авторизацию попадал в три разных чанка, ни один из которых не содержал полной картины. После увеличения до 1000 символов количество чанков упало с 203 до 104, а качество ответов выросло.

### LLM-грейдер блокировал документы с незнакомой терминологией

Самая интересная проблема. `find_relevant_docs` находил правила единорогов с хорошим score (0.78–0.80), а `ask_question` возвращал «В документации не найдена информация».

Причина: в Corrective RAG есть узел `grade_chunks`, где LLM оценивает релевантность каждого чанка перед генерацией ответа. Промпт был:

> «Документ содержит информацию, **полезную** для ответа на вопрос?»

Маленькая модель видела незнакомые слова — «тилимилитрямдия», «рогосигнал», «лунный светофор» — и отвечала `{"relevant": false}` на все чанки. После двух безуспешных retry граф уходил в финализацию с пустым ответом.

Поток при ошибке:
```
retrieve → score=0.80 ✅ (векторный поиск нашёл)
     ↓
grade_chunks → LLM: "незнакомые слова" → relevant: false ❌
     ↓
has_relevant_docs = False → prepare_retry × 2
     ↓
generate → "В документации не найдена информация" ❌
```

Исправление — переформулировать критерий грейдинга:

| | Было | Стало |
|-|------|-------|
| Критерий | «полезен для ответа» | «относится к той же теме» |
| Инструкция | — | База знаний может содержать специализированные и выдуманные термины — это нормально |
| Порог | строгий | частичное совпадение темы считается релевантным |

**Урок:** LLM-грейдер в Corrective RAG — дополнительный фильтр, и если он плохо откалиброван, он блокирует правильные результаты. Для маленьких моделей (3B) критерий должен быть максимально конкретным и не требовать суждений за пределами их возможностей.

### Windows-специфичный баг в тестах

ChromaDB держит блокировку на `chroma.sqlite3`, и стандартный `TemporaryDirectory` не мог удалить файл при выходе из контекста — тест падал с `PermissionError`. Решение: `tempfile.mkdtemp()` + `shutil.rmtree(tmpdir, ignore_errors=True)` в блоке `finally`.
