# Процесс работы со спринтами

## Методология

Команда TaskFlow работает по Scrum с двухнедельными спринтами. Спринт начинается в понедельник и заканчивается в пятницу через неделю.

## Церемонии

### Sprint Planning (понедельник, 1 час)
- Product Owner представляет приоритизированные User Stories
- Команда оценивает задачи в Story Points (Fibonacci: 1, 2, 3, 5, 8, 13)
- Velocity команды: ~40 SP за спринт
- Задачи разбиваются на технические подзадачи в TaskFlow
- Каждая подзадача получает estimate_hours

### Daily Standup (ежедневно, 15 минут)
- Что сделал вчера?
- Что планирую сегодня?
- Есть ли блокеры?
- Обновление статусов задач в TaskFlow

### Sprint Review (пятница последней недели, 1 час)
- Демо завершённых фич
- Обратная связь от стейкхолдеров
- Обновление Product Backlog

### Sprint Retrospective (пятница, 30 минут)
- Что прошло хорошо?
- Что можно улучшить?
- Action items на следующий спринт

## Статусы задач

```
[Todo] → [In Progress] → [Review] → [Done]
   ↑                        │
   └────────────────────────┘ (returned for rework)
```

### Todo
Задача создана, ожидает начала работы. Assignee может быть не назначен.

### In Progress
Разработчик активно работает. Обязательно должен быть assignee. Разработчик создаёт feature branch и начинает работу.

### Review
Pull Request создан, ожидается code review. В TaskFlow автоматически отправляется уведомление reviewers.

### Done
PR смёржен, задача закрыта. Автоматически выставляется completed_at.

## Приоритеты

| Приоритет | Описание | SLA |
|-----------|----------|-----|
| Critical | Блокер для релиза или production-инцидент | Начать немедленно |
| High | Важная фича или серьёзный баг | В текущем спринте |
| Medium | Обычная задача | В ближайших 2 спринтах |
| Low | Nice-to-have, улучшения | Когда будет время |

## Метки (Labels)

Стандартные метки для задач:
- `backend` (синий) — работа на бэкенде
- `frontend` (зелёный) — работа на фронтенде
- `bug` (красный) — ошибка
- `feature` (фиолетовый) — новая функциональность
- `tech-debt` (оранжевый) — технический долг
- `docs` (серый) — документация
- `infra` (жёлтый) — инфраструктура, CI/CD
- `security` (тёмно-красный) — безопасность
